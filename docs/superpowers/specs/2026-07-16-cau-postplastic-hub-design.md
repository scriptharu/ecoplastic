# 중앙대학교 포스트 플라스틱 허브 사이트 — 설계 문서

- **작성일**: 2026-07-16
- **상태**: 승인됨 (구현 계획 작성 대기)
- **참조 사이트**: https://www.biocycle.org/main/ (CE:PLAHUB, 서울과학기술대 포스트 플라스틱 플랫폼)

## 1. 개요 및 목표

서울과학기술대의 "포스트 플라스틱 플랫폼(CE:PLAHUB)"과 동일한 주제(탈플라스틱·순환경제 인재양성)를 다루는 **중앙대학교 버전** 콘텐츠 사이트를 구축한다.

**핵심 요구사항**
- 회원가입 없음 — 방문자는 열람만 한다.
- 공지 등 콘텐츠는 **담당자(관리자)만** 등록/수정/삭제할 수 있다.
- 데이터베이스를 사용하지 않는다.
- **GitHub Pages**를 통한 무료 정적 호스팅.
- 담당자는 **비개발자**이므로, 웹 브라우저에서 글을 작성할 수 있어야 한다(Git·마크다운 지식 불필요).

**성공 기준**
- 담당자가 브라우저에서 로그인 → 글 작성 → 발행만으로 사이트에 콘텐츠가 반영된다.
- 서버·DB 없이 GitHub Pages에서 무료로 상시 운영된다.
- 중앙대 브랜딩과 참조 사이트 수준의 레이아웃을 갖춘다.

## 2. 기술 스택 (결정)

| 영역 | 선택 | 이유 |
|------|------|------|
| 정적 사이트 생성기 | **Astro** | 콘텐츠 중심, 마크다운 컬렉션으로 목록/상세 자동 생성, 최소 JS, GitHub Pages 친화 |
| 관리자 CMS | **Sveltia CMS** (Decap 호환) | 비개발자용 웹 편집 UI, GitHub 백엔드에 직접 커밋, 무료 |
| 호스팅 | **GitHub Pages** | 무료 정적 호스팅 |
| 배포 자동화 | **GitHub Actions** | push 시 Astro 빌드 → Pages 배포 |
| 인증 | **GitHub OAuth** (Cloudflare Worker 인증 핸들러, 최초 1회 설정) | 담당자가 "GitHub 로그인"으로 접근, 별도 서버 불필요 |

> **DB 대체**: 모든 콘텐츠는 GitHub 저장소 안의 마크다운(`.md`) 파일로 존재한다. 저장소가 사실상의 콘텐츠 저장소 역할을 한다.

**검토했으나 채택하지 않은 대안**
- *커스텀 관리자 페이지 + GitHub 개인 토큰*: 인증 서버는 필요 없으나 토큰 발급이 기술적이고 편집기를 직접 구현해야 함.
- *순수 HTML + Decap CMS*: 빌드는 없으나 게시판 목록/상세를 수동 템플릿으로 관리해야 해 확장성이 낮음.

## 3. 아키텍처

```
방문자 ──열람──► GitHub Pages (정적 사이트, Astro 빌드 결과)
                      ▲
                      │ 배포
                GitHub Actions (Astro 빌드)
                      ▲
                      │ push 트리거
담당자 ─►/admin─► Sveltia CMS ──커밋──► GitHub 저장소
         (GitHub 로그인)              (content/*.md, public/uploads/*)
```

**데이터 흐름**: 담당자가 CMS에서 글 발행 → 저장소에 `.md` 파일 커밋 → GitHub Actions가 Astro 빌드 → GitHub Pages 갱신(약 1분) → 방문자에게 반영.

**핵심 원칙**: 서버·DB 없음. 회원가입 없음(방문자 읽기 전용). 콘텐츠 = 저장소 내 마크다운 파일. 쓰기 권한은 저장소 협업자로 등록된 담당자 GitHub 계정에만 부여.

## 4. 사이트 페이지 구조

```
/                     홈 (히어로 배너 + 최신 공지·뉴스 요약 + 소개 섹션)
/about                About — 사업단/연구그룹 소개, 참여 교수·팀 (정적)
/notices              공지사항·세미나·행사  [관리자 게시판 ①]
/notices/[슬러그]      상세
/news                 이슈·뉴스            [관리자 게시판 ②]
/news/[슬러그]         상세
/resources            전문정보·자료실       [관리자 게시판 ③]
/resources/[슬러그]    상세
/admin                Sveltia CMS (담당자 전용, 검색엔진 비노출)
/404                  중앙대 브랜딩 안내 페이지
```

**공통 레이아웃**
- 헤더: 중앙대 로고 + 사이트명 + 네비게이션(About / 공지사항 / 이슈·뉴스 / 전문정보), 중앙대 블루 계열.
- 푸터: 연락처, 주소, 관련 링크.
- 반응형(모바일·태블릿·데스크톱).

**게시판 공통 패턴 (목록 → 상세)** — 세 게시판이 동일한 목록/상세 컴포넌트를 재사용하고, 읽어올 콘텐츠 컬렉션만 다르게 지정한다.
- 목록: 최신순 정렬, 카테고리·날짜 표시, 페이지네이션 또는 "더보기".
- 상세: 제목·날짜·본문(마크다운 렌더링)·이미지·첨부/링크.

**홈페이지**: 히어로 배너 + "최신 공지"/"최신 뉴스" 카드 자동 노출 + 짧은 소개 섹션.

## 5. 콘텐츠 데이터 모델

각 글은 마크다운 파일 하나. 예: `content/notices/2026-07-16-세미나-안내.md`

```markdown
---
title: "제7회 순환경제 세미나 안내"
date: 2026-07-16
category: "세미나"
thumbnail: "/uploads/seminar.jpg"     # 선택
attachments:                          # 선택
  - name: "발표자료.pdf"
    url: "/uploads/slides.pdf"
externalLink: "https://..."           # 선택 (뉴스 등)
draft: false
---

본문(마크다운).
```

**게시판별 필드**

| 게시판 | 컬렉션 | 필드 |
|--------|--------|------|
| 공지·세미나·행사 | `notices` | title, date, category(공지/세미나/행사), body, thumbnail?, attachments?, draft |
| 이슈·뉴스 | `news` | title, date, category(정책/보고서/인터뷰/채용), body, thumbnail?, externalLink?, draft |
| 전문정보·자료실 | `resources` | title, date, category(논문/자료/인턴십), body, attachments?, externalLink?, draft |

**Astro 콘텐츠 컬렉션 스키마**로 위 필드를 정의한다. 필수 필드 누락·형식 오류 시 빌드가 실패하여 잘못된 페이지가 배포되지 않는다.

**첨부/이미지**: `public/uploads/`에 함께 커밋되어 GitHub Pages에서 무료 호스팅.

## 6. 관리자(담당자) 사용 흐름

```
1. 브라우저에서  <사이트주소>/admin  접속
2. "GitHub로 로그인" 클릭 (최초 1회 권한 승인)
3. 게시판 선택 (공지 / 뉴스 / 자료실)
4. "새 글" → 제목·날짜·카테고리 입력, 본문 작성(워드처럼),
   이미지·첨부는 드래그 업로드
5. "발행(Publish)" → 저장소에 자동 커밋
6. 약 1분 뒤 실제 사이트에 반영 (자동 빌드·배포)
   수정/삭제도 같은 화면에서 처리.
```

- 담당자는 Git·마크다운 지식 불필요. CMS가 폼과 파일 저장을 대신한다.
- **권한 통제**: 저장소 쓰기 권한을 가진 GitHub 계정만 발행 가능 → 담당자 계정을 협업자로 1회 추가. 이것이 "관리자만 등록"을 보장한다.
- **임시저장**: `draft: true`로 저장하면 사이트에 노출되지 않는다.
- **미리보기**: CMS 화면에서 발행 전 렌더링 미리보기.

## 7. 오류 처리 / 엣지 케이스

- **빈 게시판**: "등록된 글이 없습니다" 안내.
- **필수 필드 누락**: 빌드 실패 + 원인 표시. 깨진 페이지 미배포.
- **이미지 누락**: 기본 대체 이미지.
- **404**: 중앙대 브랜딩 안내 페이지.
- **빌드 실패 시**: 직전 성공 버전 유지(다운타임 없음), Actions 로그로 원인 확인.
- **발행 반영 지연**: "발행 후 약 1분 뒤 반영" 안내를 매뉴얼/화면에 명시.

## 8. 배포

- `main` push → GitHub Actions → Astro 빌드 → GitHub Pages 배포(약 1분).
- 기본 주소: `<사용자명>.github.io/<저장소명>`. 커스텀 도메인 연결 가능(선택).
- 최초 1회: GitHub OAuth 앱 등록 + Cloudflare Worker 인증 핸들러 배포(무료). 셋업 가이드 함께 제공.

## 9. 테스트 / 검증

- **빌드 검증**: CI 빌드 성공으로 콘텐츠·스키마·링크 무결성 확인.
- **내부 링크 체크**: 빌드 시 깨진 링크 검사.
- **반응형 확인**: 모바일/데스크톱 레이아웃 육안 검증.
- **관리자 흐름 리허설**: 배포 후 테스트 글 작성·발행·삭제로 담당자 흐름 검증.
- **접근성 기본**: 시맨틱 마크업, 이미지 alt, 색 대비.

## 10. 전달물

- Astro + Sveltia 기반 사이트 소스 (GitHub 저장소).
- GitHub Actions 배포 워크플로.
- 인증(OAuth Worker) 셋업 가이드.
- **담당자용 한글 "글 올리는 법" 매뉴얼**(스크린샷 포함).

## 11. 범위 밖 (YAGNI)

- 방문자 게시판/Q&A/댓글(회원가입·DB 필요로 제외).
- 다국어(초기엔 한국어만).
- 검색 기능(초기 범위 밖, 필요 시 후속).
- 방문자 통계/애널리틱스(후속 선택).

## 12. 미정 / 구현 단계에서 확정할 사항

- 실제 사이트명(중앙대 사업단 정식 명칭), 로고 이미지, About 본문, 초기 공지 — **담당자가 실제 콘텐츠 제공 예정**.
- 중앙대 브랜드 컬러 정확한 색상값(구현 시 확정).
- 저장소 이름 및 GitHub 조직/계정.
